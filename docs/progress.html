Implementation status · 2026-10-26Passing 3.5 MeV alpha guiding centres confined for all time in an exact stellarator field for every pitch parameter λ ∈ [0, 1/4] (the limit of the passing argument) at one energy and B₀R₀, and over a positive-measure velocity set with |E − 3.5 MeV| ≤ 0.4 eV × λ ∈ [0, 1/16] (Littlejohn model; vacuum model field; heavy certificates on demand, workstation cells spot-checked), and for μ = 0 over B₀R₀ ∈ [67.95, 69.99] T·m; a Mercier-stable finite-β non-axisymmetric band with labels derived from the field, whose ballooning stability is reduced to one pointwise certificate but not yet certified; all-time field-line confinement; 52-transit coil confinement; one exact axisymmetric field with alpha confinement and a hot-core, pressure-budget band for every supplied transport solution (existence not proved), with certified local stability, up to ignition; kernel checks under 6 GB per process; most decide +kernel calls replaced by explicit proof-term certificates; a workstation pipeline in use. Compiled declarations, build results and assumptions → Chapter notes retain their original planning context; the task progress fields report subsequent work.

Outcome

This run combines five pitch-angle cells into one all-time confinement theorem covering the whole passing range λ ∈ [0, 1/4]. Three of the cells were computed on the workstation. Kernel-check memory is halved, and most decide +kernel calls are replaced by explicit proof-term certificates. The library still has no project axioms. The heavy results are audited separately (scripts/check_axioms_heavy.lean).

  • Every pitch parameter up to the passing limit (Design.RationalStellaratorGC.alpha_gc_passing_confined_forever_quarter, gc_mu_passing_confined_forever_SI_quarter, rationalStellarator_gc_mu_confined_forever_quarter, quarter_passing_margin, quarter_cells_cover).
  • Statement: fix the design B₀R₀ = 256 m v/(2e) ∈ [68.9, 69] T·m. Then passing (v_∥(0) > 0) 3.5 MeV alpha guiding centres with every μ ∈ [0, E/(4B₀)] (λ = μB₀/E ∈ [0, 1/4]) that start inside the exact KAM torus stay inside it for all time. They also stay passing: λ|B| ≤ 3/4 is proved, so E − μ|B| ≥ E/4.
  • Pitch angles: initial pitch angles satisfy sin²χ ≤ |B|/(4B₀), about χ ≲ 30° near the axis (an informal reading).
  • λ = 1/4 is the limit of the present passing argument: the tube lemma needs λ ≤ 1/4, given the proved bound |B| ≤ 3B₀.
  • Cells: the theorem combines five certified cells.
  • [0, 1/16] is Mu (default build).
  • [1/16, 1/8] is Mu2, from report 13.
  • [1/8, 3/16] is Mu3, rebuilt on the laptop after the generator fix below.
  • [3/16, 7/32] is Mu4 and [7/32, 1/4] is Mu5. Both were computed on the workstation (24 CPU-min each, peak 4.1 GB).
  • Build: on-demand, lake build PlasmaLean.Design.RationalStellaratorGCMuQuarter. The module is not imported by PlasmaLean.lean. It was built on the laptop from Mu2–Mu5 compiled on the workstation, copied with oleans.py (400 modules, 314 MB, Linux → Mac; Lake accepted them without rebuilding).
  • Scope: one energy and one B₀R₀. The set has positive measure in pitch angle but measure zero in 3-D velocity space. Littlejohn guiding-centre model (supplied, not derived), non-relativistic and collisionless, static vacuum model field (not coil-produced). The on-demand cells Mu2–Mu5 were spot-checked on the laptop (a sample of modules built, the workstation's measurements and axiom checks inspected), not fully rebuilt.
  • Pitch cells beyond 1/8: per-node majorants (Theory/KAM/PolyExprSMajQG, default build). The first workstation run for [1/8, 3/16] failed. One uniform bound for the three inverse-square-root nodes is impossible for λ₁ > 1/(4·mQQ) ≈ 0.157. This was a limit of the bound, not of the field. Per-node majorants only need λ₁·mQQ·gE·gE4 < 1, which is 0.47 at λ₁ = 1/4.
  • Low-memory kernel checks (Certificates/KronLowMemCompute, KronBallLowMem).
  • Diagnosis: the memory was in the kernel's whnf caches of big intermediate numbers.
  • Fix: sign–magnitude integers, per-row masks placed by divide and conquer, and row block sums by two multiplications. Bridge lemmas re-prove the original statements, so chains and theorems are unchanged.
  • Result: peak per process 8.8 → 4.3 GB in both the default build and the on-demand families. Check CPU is about halved (Mu H 554 → 329 s, Ew H 2,596 → 1,437 s). The 6 GB laptop target now holds everywhere.
  • Phase 16: proof-term certificates; no decide +kernel. Large checks become explicit proof terms in the pattern of PlasmaLean/SubsetSum.lean. Each certificate is an inductive predicate whose constructors are local steps, with soundness proved by induction. A meta builder constructs the certificate, and the leaves are small kernel Nat facts closed by Eq.refl.
  • Tools (default build):
  • Certificates/KronProof (SCert, PCert, tactics kron_proof, kron_lt) for the Kronecker ball checks;
  • Certificates/KernelFact (kernel_fact) for side conditions;
  • Certificates/KronProof2D (kron2_proof, PCert2) for the older Torus/NegTorus format;
  • Certificates/BoolCert (bool_cert), with one constructor per local step of a Boolean checker;
  • Certificates/DigitSumCert (l1kron_cert);
  • Certificates/EvalCert (ECert, eval_cert, fiv_cert; Design/SolovevBallooningEvalCert, bl_cert), with one node per operation of the term tree and shared intermediate values. The builder is compiled to native code in a new library PlasmaLeanMeta (precompileModules), which cut the builder cost from ≈ 3.2 s to 0.3 s per leg check. It supports ℚ values in normal form.
  • All KAM families converted: Mu and Fam on the laptop; Mu2–Mu5 and Ew1–Ew4 on the workstation (task proofterm-migrate, spot-checked). This includes the Env/Out side conditions.
  • Heavy evaluation certificates. The user decided to accept large private oleans for fully explicit certificates, which adds about 9 GB of local build files. These files are not in git and not loaded by importers. Converted:
  • the near-axis oscillation leg checks (262 uses, 300–314 MB per module);
  • the Solov'ev ballooning corner tests (1,413 uses);
  • the Solov'ev band piece checks (39 uses).
  • Counts: at the start of Phase 16 there were about 28,724 uses of decide +kernel in 813 files. About 5,700 remain (5,673 lines containing it), and the default build has about 1,400 (1,407 lines).
  • Open items:
  • Polygon-coil lines need a new design. Done fully explicitly, one grid line is 1.18×10⁶ nodes (268 s, 5.9 GB, ≈ 400 MB of olean). All 690 lines would take ≈ 50 CPU-hours and ≈ 280 GB.
  • A few opaque leaves remain. These are not decide +kernel but are one Eq.refl on a whole check: Ballooning hessOK in ballooning_cover, box_accepted/axisOK_needs_positive, and the Kronecker-image equalities of the chains.
  • Also open: the QPoly.checkOn fixtures, and ValidatedBVP/Slab (these need Finset support).
  • Phase 15: the workstation pipeline in use. See Workstation.md and workstation/REVIEWED.md.
  • Runs: scripts/workstation/run.sh ran 11 tasks on the workstation hornbill. Its push check now fails fast on password prompts, it commits the generated files of failed tasks, and it stashes leftovers before returning to main.
  • Review: the skill plasmalean-workstation-update fetches, re-checks and merges the runs, and keeps the "Next Commands" section of Workstation.md current.
  • Spot-check policy (user decision): on-demand results are spot-checked, not rebuilt in full on the laptop. Default-build results are always rebuilt.
  • scripts/workstation/oleans.py packs and unpacks compiled modules between machines. Before extracting, it checks that the Lean version, the manifest and the sources match. Copying from Linux to the Mac was verified.
  • Failures, recorded honestly:
  • the uniform-majorant failure above;
  • a false Mu3Adm bound, caused by a generator bug (see Corrections);
  • the full cell [3/16, 1/4], which failed KAM smallness (2.64 > 1): the residual and C₂ grow with λ at fixed width (Mu2 0.158, Mu3 0.50). It was halved into Mu4 and Mu5, and both passed.

Corrections and challenged claims

  • Generator double substitution (bug, fixed). lam_emit_kam.py replaced template literals one after another. A new value equal to a later template literal was therefore replaced again: for Mu3, az0 = 1629/10⁴ became 1623/10⁴, a false bound in Mu3Adm. The kernel rejected it, so nothing false was proved. The emitter now does one regex pass with digit boundaries. Before writing, scripts/gc_kam/lamcell/validate.py checks every emitted bound and constant in exact arithmetic against the emitted Lean lists. That validator caught the 2.64 smallness failure before any Lean was written.
  • Stale-cache hazard. A stale Mu4 work directory on the workstation could have fed old numerics into a new run. It was cleared before the run, and the hazard is noted in the run instructions.
  • Env/Out files left uncommitted (fixed). The workstation proof-term runs patched the Env/Out side-condition modules but did not commit them, so the merged branches still had decide +kernel there. These were converted on the laptop (385746c). proofterm_emit.py now commits what it patches, and run.sh stashes leftovers.
  • "One consistent plasma" overstated (audit correction, wording only). solovev_one_plasma_actual and its _coarea, _highQ and _ignited variants take a classical solution of the radial transport model as a hypothesis; existence is not proved. Force balance uses the offset pressure p_eq + 40 kPa (90 kPa ignited), and the thermal pressure is bounded by that budget, not equal to it. The claim is now called "one field with a pressure-budget band" in the README, slides and site; the theorems are unchanged.
  • Memory correction from report 13 resolved. The 8.8 GB peak reported there is now 4.3 GB.
  • Scope, unchanged. The λ ∈ [0, 1/4] theorem is for one energy and one B₀R₀. It is not positive measure in 3-D velocity space; only the earlier ±0.4 eV energy window with λ ∈ [0, 1/16] is. It uses the Littlejohn model (supplied), is collisionless, and uses the vacuum model field, not a coil-produced field. Trapped alphas are not covered. On-demand modules computed on the workstation were spot-checked on the laptop, not fully rebuilt, so trusting them means trusting the workstation's kernel run for the unsampled modules.
